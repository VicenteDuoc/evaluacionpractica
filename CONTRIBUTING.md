# #️⃣ GUÍA DE CONTRIBUCIÓN: BUENAS CONDUCTAS 🚀

¡Hola! Antes de empezar a picar código en **VS Code**, lee esta guía para mantener nuestro entorno de trabajo sano y profesional.

---

## 📋 CÓDIGO DE CONDUCTA EN EL TRABAJO

### *1. Comunicación y Respeto*
* **Empatía ante todo:** Detrás de cada Pull Request hay un compañero. Sé amable en tus comentarios.
* **Crítica constructiva:** Si encuentras un error, propón una solución. Usa: *"Podríamos mejorar esto así..."* en lugar de *"Esto no sirve"*.
* **Sin ruidos:** No utilices los canales de Issues o comentarios para chats personales.

### *2. Higiene del Editor (VS Code)*
* **Usa las Recomendaciones:** Instala las extensiones sugeridas en `.vscode/extensions.json` para que todos tengamos el mismo linter.
* **Respeto al Formateo:** No cambies la configuración de `Editor: Tab Size` a tu gusto personal si el proyecto ya tiene una definida. **¡Mantén la consistencia!**
* **Limpieza de Archivos:** Antes de hacer commit, asegúrate de no estar enviando archivos temporales o carpetas `.logs`.

---

## 🛠️ PASOS PARA COLABORAR

### **Paso 1: Preparación**
* Haz un **Fork** del repositorio.
* Crea una rama con un nombre claro: `git checkout -b feature/mejora-interfaz`.

### **Paso 2: Desarrollo Ético**
* **Escribe código legible:** No intentes ser el más listo haciendo código en una sola línea que nadie entienda.
* **Comenta lo necesario:** Usa los comentarios para explicar el **porqué**, no el *qué*.
  > *Ejemplo: // Usamos este timeout porque la API externa tarda en responder.*

### **Paso 3: El Pull Request (PR)**
* Describe tus cambios usando la plantilla de PR.
* Si hiciste cambios visuales, añade una captura de pantalla directamente en el comentario.
* **Auto-Review:** Revisa tu propio código en la pestaña de `Source Control` de VS Code antes de subirlo. ¡Te sorprenderá lo que encuentras!
